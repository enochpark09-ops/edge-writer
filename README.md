## v2.0 변경사항

### 1. API 키 노출 차단 (보안 — 중요)

v1.x는 `import.meta.env.VITE_ANTHROPIC_API_KEY`를 썼다. Vite는 `VITE_` 접두사 변수를 **빌드 시 번들에 그대로 박아 넣으므로**, 배포된 사이트에서 개발자도구를 열면 누구나 API 키를 읽을 수 있었다.

v2.0은 `api/review.js` 서버리스 함수를 경유한다. 키는 서버에만 남는다.

> **v1.x를 배포한 적이 있다면 기존 Anthropic API 키를 폐기하고 재발급하세요.**

### 2. 문서 4종 → 6종

기획안·설정집·인물집·로드맵에 **메타스키마**와 **떡밥장부**가 추가됐다.

| 문서 | 성격 | 갱신 빈도 |
|---|---|---|
| 기획안 | 규칙 | 거의 없음 |
| 설정집 | 세계관 | 몇 회차마다 |
| 인물집 | 인물 | 가끔 |
| 로드맵 | 시간축 | 10화 단위 |
| **메타스키마** | 규약 | 거의 없음 |
| **떡밥장부** | 추적 | **매 회차** |

### 3. 감수 3종 분리

하나의 프롬프트가 설정 모순과 수위 위반과 페이스 문제를 동시에 보면 어느 하나가 흐려진다. 감수자를 나누고, 각자에게 필요한 문서만 준다.

| 감수자 | 직무 | 주입 문서 |
|---|---|---|
| **감(監)** | 설정 일관성·문체·분량·훅·메타블록 | 기획안·설정집·인물집·메타스키마 |
| **어사(御史)** | 수위·연령·관능묘사 원칙·법무 | 기획안·인물집 |
| **도목수(都木手)** | 로드맵 이탈·떡밥 적체·인물 방치·페이스 | 로드맵·떡밥장부·기획안 |

감수는 **자문**이다. 고·중 심각도가 남아 있어도 확정할 수 있고, 그때 확인 창이 뜬다. 결정은 대표가 한다.

### 4. 메타 블록 자동 파싱

원고 말미의 `### 메타 · SCHEMA v1` 블록에서 떡밥·설정 신규·등장인물·수위·시기를 뽑아낸다. 원고를 붙여넣는 즉시 요약이 뜨고, 저장하면 떡밥 장부와 설정 등재 대기 목록에 자동 반영된다.

분량 검산도 한다. `@분량`에 적힌 값과 실제 본문이 200자 넘게 벌어지면 경고한다.

### 5. 확정 원고 클라우드 보관

`임시 저장`과 `원고 확정` 두 단계. 확정하면 `confirmed_at`이 박힌다.

원고를 고칠 때마다 **DB 트리거가 이전 본문을 `episode_versions`에 자동으로 떠 넣는다.** 실수로 덮어써도 이전 원고는 남는다.

## 설치

### 1. Supabase

1. [supabase.com](https://supabase.com)에서 프로젝트 생성
2. SQL Editor에 `db/schema.sql` 전체를 붙여넣고 Run
3. Authentication → Providers → **Email** 켜기 (매직 링크 로그인)
4. Settings → API에서 `Project URL`과 `anon public` 키 복사

### 2. Vercel 환경변수

Settings → Environment Variables

| 이름 | 값 | 비고 |
|---|---|---|
| `ANTHROPIC_API_KEY` | `sk-ant-...` | **`VITE_` 접두사 금지.** 붙이면 다시 공개된다 |
| `ANTHROPIC_MODEL` | `claude-sonnet-4-6` | 선택 |
| `EDGE_WRITER_SECRET` | 임의 문자열 | 선택. 프록시 접근 제한 |
| `VITE_SUPABASE_URL` | `https://xxx.supabase.co` | 공개되어도 됨 |
| `VITE_SUPABASE_ANON_KEY` | `eyJhbGci...` | 공개되어도 됨 (RLS가 방어선) |
| `VITE_EDGE_SECRET` | `EDGE_WRITER_SECRET`과 같은 값 | 위를 설정했다면 |

### 3. 배포

```bash
npm install
npm run build
```

Vercel은 루트의 `api/` 폴더를 자동으로 서버리스 함수로 배포한다. Vite 빌드와 별개로 동작한다.

로컬 테스트는 `vercel dev`를 쓴다 (`npm run dev`만으로는 `/api/review`가 뜨지 않는다).

## 사용 흐름

1. **작품 서재**에서 작품 선택, 또는 `+ 작품 등록`으로 문서 6종 붙여넣기
2. 회차 표기 입력 — **`1부-004` 형태**로 적어야 part/no가 분해된다
3. 원고 붙여넣기 (메타 블록까지 함께)
4. 감수자 선택 → **감수 실행**
5. 수정 후 **재감수** — 이전 지적의 해결 여부를 대조한다
6. **임시 저장** 또는 **원고 확정**
7. **타임라인 반영** — 이후 회차 감수의 시계열 기준이 된다

## 데이터

- 클라우드(Supabase)가 주 저장소, localStorage가 오프라인 캐시
- 환경변수가 없으면 **클라우드 없이 localStorage만으로도 동작한다** (v1.x와 동일)
- `백업 내보내기/불러오기`(JSON)는 그대로 유지

## 문서 관리 원칙

- **기획안 / 설정집 / 인물집 / 메타스키마**: 거의 바뀌지 않는 기준 문서
- **로드맵**: 10화 구간을 다 쓰면 다음 구간을 하단에 추가. 앞부분은 지우지 않는다
- **떡밥장부**: 회차마다 갱신. ID는 한 번 발급하면 영구히 바뀌지 않고, 폐기해도 재사용하지 않는다
- 로드맵이 너무 길어지면 완결 구간은 요약으로 압축하고 다음 예정 구간만 상세히 둔다
